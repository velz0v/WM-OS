# Безопасность WM OS

Этот документ описывает **реализованные** меры и явно перечисляет то, чего в коде нет.
WM OS — локальное приложение, но «локально» не означает «зашифровано»: Android sandbox,
Keystore и шифрование всей базы — разные вещи.

## 1. Модель угроз

### 1.1 Что защищаем

| Актив | Где лежит | Чувствительность |
|---|---|---|
| Заметки, памятки, ссылки, тексты | Room `wm_os.db` | Высокая |
| Задачи, проекты, напоминания | Room `wm_os.db` | Средняя/высокая |
| Входящие файлы (изображения, PDF) | `filesDir/inbox/` | Высокая |
| Черновики редактора | `SharedPreferences "wm_drafts"` | Высокая |
| API-ключи провайдеров | `EncryptedSharedPreferences "wm_secrets"` | Критическая |
| История чатов Грауса | Room | Высокая |
| Журнал действий | Room `action_log` | Средняя |
| Экспорт JSON/Markdown | Внешнее место, выбранное через SAF | Высокая |
| Настройки | DataStore `wm_settings` | Низкая/средняя |

### 1.2 От кого/чего защищаемся

| Угроза | Реализованная защита | Остаточный риск |
|---|---|---|
| Другое приложение читает данные | Android sandbox, private app storage | На rooted/скомпрометированном устройстве sandbox не спасает |
| Кража устройства | Экран блокировки ОС, `VISIBILITY_PRIVATE` уведомлений | **Нет** блокировки самого WM OS, нет `FLAG_SECURE`, содержимое видно в recents |
| Утечка API-ключа | Keystore + EncryptedSharedPreferences, в БД только alias | Компрометация Keystore/разблокированного устройства, alpha-версия `security-crypto` |
| Ключ попал в Git/логи | `.gitignore`, ключи не пишутся в логи, нет аналитики | Нет CI secret scanning; человеческий фактор |
| Перехват трафика к AI | Только HTTPS, стандартная проверка сертификатов OkHttp | Нет certificate pinning; доверенные CA и подмена DNS остаются риском |
| Prompt injection в заметке/файле | Allowlist инструментов, подтверждение мутаций, проверка результата | Нет детектора инъекций; содержимое заметок уходит модели при поиске |
| Случайная отправка лишнего AI | Контекст ограничен сообщением, историей и результатами инструментов | Настройка `sendNoteContentToAi` не применяется; `search_brain` отдаёт сниппеты |
| Потеря данных | WAL, отсутствие destructive fallback, черновики | Нет импорта/restore, нет шифрованного backup, нет теста восстановления |
| Повреждение БД | Room, WAL | Нет экспорта диагностики/восстановления |
| Вредоносный файл | Файлы только копируются в private storage, не исполняются | Нет парсеров/OCR; MIME не проверяется по сигнатуре |
| Утечка через системный backup | `allowBackup=false` + data extraction rules исключают всё | Пользователь может сам экспортировать открытый JSON |
| Подмена провайдера | URL сохраняется пользователем, HTTPS обязателен | Нет allowlist доменов; пользователь может указать любой HTTPS-host |

## 2. Хранение данных

| Данные | Механизм | Шифрование |
|---|---|---|
| Основная БД | Room/SQLite, `wm_os.db`, WAL, private app storage | **Нет** прикладного шифрования; только sandbox ОС |
| Вложения Inbox | `filesDir/inbox/<id>_<name>` | **Нет** |
| Черновики | `SharedPreferences("wm_drafts")`, JSON-строка | **Нет** |
| Настройки | Preferences DataStore `wm_settings` | **Нет** |
| API-ключи | `EncryptedSharedPreferences("wm_secrets")` | Да: AES-256-GCM значения, AES-256-SIV ключи, master key в Android Keystore |
| Экспорт | Файл, выбранный пользователем через SAF | **Нет**, открытый JSON/Markdown |
| Системный backup | Отключён | — |

В `AndroidManifest.xml`:

```xml
android:allowBackup="false"
android:fullBackupContent="false"
android:dataExtractionRules="@xml/data_extraction_rules"
```

`data_extraction_rules.xml` исключает `root`, `file`, `database`, `sharedpref`, `external`
и для cloud-backup, и для device-transfer. Это защищает от случайной синхронизации БД,
черновиков и ключей через системный backup, но **не** заменяет шифрование.

### 2.1 Чего нет

* **Полного шифрования базы нет.** SQLCipher и аналог не подключены. Любой, кто получит
  файл `wm_os.db` (root, adb backup при изменённых настройках, физический доступ к data),
  прочитает заметки, задачи и чаты.
* **Шифрования вложений нет.**
* **Шифрования черновиков нет.**
* **Шифрованного backup нет.** Экспорт — открытый текст.
* **Автоматического удаления по retention нет.** `trashRetentionDays` сохраняется, но не
  применяется; данные не исчезают «сами».

## 3. API-ключи

### 3.1 Схема

```text
AIProviderEntity.secretAlias  ──►  EncryptedSharedPreferences "wm_secrets"
                                      master key: Android Keystore
                                      AES-256-GCM (значение)
                                      AES-256-SIV (имя ключа)
```

* ключ генерируется при первом обращении к `SecretStore`;
* в Room хранится только `secretAlias` вида `prov_<uuid>_<base64>`;
* plaintext-ключ не пишется в БД, логи, экспорт, backup и не показывается в UI
  (в списке — маска);
* при удалении провайдера вызывается `secrets.delete(alias)`;
* `ProviderRepository.save()` при создании требует непустой ключ, при редактировании
  пустое поле означает «оставить прежний»;
* ключ читается из хранилища непосредственно перед HTTP-запросом.

### 3.2 Ограничения

* `androidx.security:security-crypto:1.1.0-alpha06` — alpha-версия библиотеки;
* мастер-ключ привязан к Keystore и устройству; при потере ключа (сброс, повреждение
  Keystore) сохранённые секреты не восстановить — это ожидаемо, но пользователю не
  показывается отдельное предупреждение;
* ключ живёт в памяти процесса во время запроса;
* fingerprint (SHA-256, 8 символов) реализован, но не используется;
* маска показывает первые и последние 4 символа для ключей длиннее 8 символов — это
  раскрывает часть секрета в UI (осознанный компромисс для идентификации ключа).

### 3.3 Если ключ утёк

1. Немедленно отозвать ключ у провайдера.
2. Выпустить новый и заменить его в AI Lab.
3. Считать старый ключ скомпрометированным навсегда: удаление коммита/файла не делает
   его безопасным.
4. Проверить историю Git и логи CI. Никогда не публиковать сам ключ в issue/чате.

## 4. Что уходит внешнему провайдеру

Запрос Грауса содержит:

* system prompt (правила ассистента);
* историю **только** ролей `user`/`assistant` с непустым текстом;
* новое сообщение пользователя;
* результаты инструментов, которые модель вызвала в этом цикле:
  * `search_brain` — ID, заголовки, типы, `snippet` до 300 символов, `updated_at`;
  * `read_brain_item` — заголовок, тип и `content` до 4000 символов;
  * `list_tasks` — ID, названия, статусы, сроки (до 20);
  * результаты создания — ID, название, статус планирования.

Не уходит: API-ключ, `secretAlias`, пароли, настройки, вся база целиком, вложения,
журнал действий, сохранённая память (она не используется).

Важные оговорки:

* **настройка «Отправлять текст заметок в контексте» не подключена.** `GrausEngine`
  не читает `sendNoteContentToAi`; фактически текст заметки может уйти провайдеру через
  `search_brain`/`read_brain_item`, если модель их вызвала;
* провайдер получает запросы целиком и может их хранить по своим правилам; WM OS не может
  это гарантировать;
* выбранный провайдер и модель показываются в шапке Грауса и в AI Lab;
* автопереключение провайдера отсутствует (флаг `aiAutoSwitchEnabled` не используется);
* офлайн-очереди «отправить позже» нет.

## 5. Сеть

* единственный сетевой клиент — OkHttp в `AiClient`;
* URL обязан начинаться с `https://` и в `ProviderRepository.save()`, и в `AiClient.chat()`;
* стандартная проверка сертификатов не отключается, кастомного `TrustManager` нет;
* таймауты: connect 20 с, read 90 с, write 30 с, call 120 с;
* `retryOnConnectionFailure = true` — это транспортный retry OkHttp, а не бесконечный цикл;
* `Retry-After` не обрабатывается;
* тело ответа читается целиком без лимита;
* нет certificate pinning и явной проверки смены origin при redirect;
* нет прокси/аналитики/рекламных SDK и скрытой телеметрии.

## 6. Уведомления и экран блокировки

* канал `wm_reminders_v1`, `IMPORTANCE_HIGH`, `VISIBILITY_PRIVATE`, вибрация;
* содержимое уведомления (title/description) может быть видно на lock screen в зависимости
  от системных настроек пользователя; WM OS не скрывает его полностью;
* действия «Выполнено» и «Отложить» доступны с уведомления;
* `ReminderReceiver` не экспортирован;
* `BootReceiver` экспортирован (`exported=true`), но выполняет только перепланирование
  активных напоминаний из БД;
* deep link из уведомления в конкретное напоминание не реализован (`EXTRA_REMINDER_ID`
  передаётся, но `MainActivity` его не читает).

## 7. Блокировка приложения и биометрия

**Не реализовано.**

* В `AndroidManifest.xml` объявлен `USE_BIOMETRIC`, но кода `BiometricPrompt`,
  `KeyguardManager` или проверки PIN нет.
* В `AppSettings` есть `appLockEnabled = false`, но настройка не показывается в UI и не
  проверяется при старте.
* Нет `FLAG_SECURE`, поэтому содержимое доступно в списке недавних приложений и на
  скриншотах.
* Нет авто-блокировки после ухода в фон.
* Нет скрытия контента в recents.

Это критично для сценария «кража разблокированного устройства»: после разблокировки ОС
приложение открывается без дополнительной проверки.

## 8. Импорт, экспорт и backup

* Импорт файлов отсутствует; путь «пользователь выбрал файл → приложение разобрало»
  сейчас существует только для Share (копирование потока в Inbox), без парсинга.
* Share принимает `text/plain`, `image/*`, `application/pdf`; файл копируется в private
  storage. Тип определяется по MIME отправителя, сигнатура не проверяется.
* Ошибка копирования даёт `FAILED`, а не ложное «Сохранено».
* Экспорт JSON/Markdown — открытый текст; SAML/шифрования нет.
* Нет проверки контрольных сумм, нет staging/транзакции восстановления, нет теста
  restore на чистом профиле.
* `BackupRepository` намеренно не содержит import-кода: непроверенный restore нельзя
  объявлять работающим.

## 9. Логи и журнал действий

* В коде нет `android.util.Log`, `println`, `printStackTrace`, Crashlytics/Firebase.
* `action_log` хранит: actor, tool, status, summary (до 500 символов), targetIds, время.
  Summary может содержать название созданной задачи/заметки и текст ошибки.
* Журнал не хранит API-ключи и полные тексты заметок, но **может** хранить название
  сущности; это не «полностью безопасный» журнал.
* Нет экспорта диагностического пакета.

## 10. Разрешения

| Разрешение | Зачем | Использование |
|---|---|---|
| `POST_NOTIFICATIONS` | Уведомления напоминаний | Запрашивается при открытии редактора напоминания на Android 13+ |
| `SCHEDULE_EXACT_ALARM` | Точные будильники | Проверяется `canScheduleExactAlarms()`, ведёт в настройки |
| `RECEIVE_BOOT_COMPLETED` | Перепланирование после reboot | `BootReceiver` |
| `INTERNET` | Запросы к AI-провайдеру | OkHttp |
| `ACCESS_NETWORK_STATE` | Объявлено | В коде не используется |
| `VIBRATE` | Вибрация уведомлений | Канал |
| `USE_BIOMETRIC` | Объявлено | **Не используется**, биометрии нет |

Приложение не запрашивает контакты, SMS, звонки, геолокацию, Accessibility, фоновую
запись аудио и не сканирует всё устройство.

## 11. Правила для секретов в репозитории

1. Никогда не коммитить реальные API-ключи, `local.properties`, keystore, `.env`.
2. `.gitignore` уже исключает `local.properties`, `*.jks`, `*.keystore`, `*.p12`, `*.pem`,
   `.env*`, `*.log`, `*.db`, `build/`, `app/build/`.
3. В тестах и примерах — только фиктивные ключи вида `sk-test-...`.
4. Не вставлять ключи в issue, Pull Request, логи CI, скриншоты и сообщения об ошибках.
5. Если ключ попал в Git — отозвать и заменить, а не просто удалить коммит.
6. Для сборки использовать локальный `local.properties`; он не должен попадать в Git.
7. Release keystore хранить отдельно от репозитория и иметь безопасную резервную копию.

## 12. Как сообщить об уязвимости

Публичный issue — не место для секретов и эксплойтов. Используйте приватный канал
GitHub Security Advisory (вкладка **Security → Report a vulnerability**) или свяжитесь
с мейнтейнером репозитория напрямую. В сообщении укажите:

* версию/коммит;
* затронутый компонент (БД, AI, backup, уведомления, импорт);
* шаги воспроизведения;
* оценку последствий;
* есть ли утёкший секрет (не прикладывайте сам ключ).

Мы постараемся подтвердить получение и согласовать срок раскрытия. Не публикуйте детали
до исправления.

## 13. Что не обещается

* «Абсолютная безопасность» и защита от скомпрометированной ОС.
* Шифрование всей базы, вложений и экспорта.
* Блокировка приложения PIN/биометрией.
* Защита от screenshot/recents.
* Certificate pinning и гарантия, что провайдер не хранит запросы.
* Восстановление данных при потере ключа Keystore.
* Проверенный backup/restore и защита от всех вредоносных файлов.
* Отсутствие секретов в APK без отдельного сканирования релизной сборки.

## 14. Статус проверок

| Проверка | Статус |
|---|---|
| `allowBackup=false` и data extraction rules | Есть |
| Ключи в EncryptedSharedPreferences + Keystore | Есть |
| Ключи не попадают в Room | Есть (только alias) |
| HTTPS-only | Есть в репозитории и клиенте |
| Логи с секретами | В коде логов нет |
| Полное шифрование БД | **Нет** |
| Блокировка PIN/биометрия | **Нет** |
| Certificate pinning | **Нет** |
| Secret scanning в CI | **Нет** (CI-конфигурации в дереве не найдено) |
| Тест restore/backup | **Нет** |
| Тест prompt injection | **Нет** |
